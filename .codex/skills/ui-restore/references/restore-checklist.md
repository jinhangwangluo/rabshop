# UI 还原执行清单

## 1. 输入清单

每次开始前确认：

- 已拿到 HTML 路径。
- 已拿到 UniApp 页面目标路径。
- 已拿到设计图、截图或页面状态图。
- 已确认多张图是否属于同一页面。

## 2. HTML 分析清单

读取 HTML 后，至少整理出以下信息：

- 页面分区结构。
- 关键文案。
- 图片与图标位置。
- 按钮、输入框、Tab、弹层等交互元素。
- 列表、卡片、空态、占位块。
- 明确可量化尺寸：`padding / margin / gap / width / height / font-size / line-height / border-radius / border / shadow`。
- 将 HTML 中的移动端 `px` 优先转换为 UniApp 可落地的 `rpx`，至少确认本页关键值，例如 `16px -> 32rpx`、`48px -> 96rpx`、`56px -> 112rpx`。

## 3. 设计图比对清单

比对设计图时，至少检查：

- 布局层级是否一致。
- 主次文字层级是否一致。
- 区块间距、边距、内边距是否一致。
- 圆角、边框、阴影是否一致。
- 背景色、按钮色、选中态颜色是否一致。
- 图标、图片、角标、标签是否一致。
- 若 HTML 已给出明确尺寸，设计图只用于校验视觉结果，不得反向凭感觉改写这些尺寸。

## 4. 多状态合并清单

若同一页面存在多张状态图，必须统一到一个页面中，至少确认：

- 哪些是默认态。
- 哪些是空态。
- 哪些是激活态。
- 哪些是弹层或抽屉态。
- 哪些是筛选或 Tab 切换态。
- 状态切换字段是否清晰、可维护。

## 5. 路由创建清单

更新 `template/uniapp/pages.json` 时检查：

- 路由是否已存在。
- 页面应放主包还是分包。
- 路径是否与实际页面文件一致。
- `navigationBarTitleText` 是否已设置。
- 当前模块若普遍使用自定义导航，是否补了 `navigationStyle: 'custom'`。
- 若使用自定义导航，是否使用全局 `<app-safe-top />` 处理顶部安全区，且该组件在 H5 不产生额外距离、在 `微信小程序` 能正确避让顶部状态栏。
- 若页面顶部需要避让小程序胶囊导航，是否通过 `<app-safe-top mp-extra="..." />` 统一处理，而不是在页面内手写独立状态栏占位或散落的 `APP-PLUS` 条件渲染。
- 若页面顶部已有设计稿留白，是否通过调整 `app-safe-top` 的 `mp-extra` 控制高度，避免额外独立占位块和原有留白叠加导致页面过低。

## 6. 语法检查清单

编码完成后，逐项检查：

- 模板标签是否闭合。
- `v-if / v-else-if / v-else` 链是否正确。
- `v-for` 是否带稳定 `key`。
- 是否误用了小程序不支持的动态组件或浏览器对象。
- 自定义导航页面是否已经校验顶部安全区，首屏内容不会在 `微信小程序` 中顶到状态栏，也不会因为占位块与头部留白叠加而整体过低。
- `methods`、`computed`、`data` 中引用是否存在。
- import、组件注册、变量声明是否一致。
- **是否已调用 `uni-css-guard` 技能完成样式跨端兼容审查**，至少确认以下 CSS 兼容项：
  - 是否使用了 `gap` 属性（小程序支持不稳定），已用 `flex + margin` 替代或条件编译兜底。
  - 是否使用了 `position: sticky`（H5 与小程序表现差异大），已评估并做分端处理。
  - 是否使用了 `100vh` / `100vw`（受 H5 地址栏/小程序安全区影响），已改用明确容器高度或安全区变量。
  - 是否使用了 `display: grid` / `grid-template-*`（小程序支持有限），核心布局已改用 flex 或条件编译。
  - 是否使用了 `overflow: auto` / `scroll`（小程序普通 view 不生效），滚动区域已改用 `scroll-view`。
  - 是否使用了 `line-clamp` / `-webkit-line-clamp`（需双写兼容），已补充标准属性。
  - 是否使用了 `backdrop-filter` / `filter`（性能与兼容问题），已提供降级方案。
  - 是否使用了 `body` / `html` / `*` 根选择器（小程序无效），已改为 `page` 或具体选择器。
  - 模板中 `:style` 绑定是否存在复杂三元嵌套或对象字面量兜底（小程序 WXML 不支持），已前置到 `computed`。
  - `position: fixed` + `bottom` 是否处理了安全区兼容（H5 tabBar / 小程序底部安全区）。
- `scss` 是否存在明显语法错误。
- lint 是否通过。

## 7. 三轮 UI 复查清单（强制量化校验）

> **核心规则：每轮必须重新读取设计图图片和 .vue 代码文件，逐项标注 PASS/FAIL，FAIL 必须修复后重跑当前轮。**
>
> **修复次数限制**：
> - 每轮最多 **2 次修复尝试**（每轮独立计算，不跨轮累计）
> - 第 1 次检查有 FAIL → 修复(1/2) → 重跑全部项
> - 第 2 次检查仍有 FAIL → 修复(2/2) → 重跑全部项
> - 第 3 次检查仍有 FAIL → **本轮额度用尽，携带 FAIL 项进入下一轮**（下一轮重新对这些项检查，享有新的 2 次修复额度）

### 第一轮：布局骨架校验（6 项）

| # | 检查项 | 校验方法 | 判定标准 |
|---|--------|----------|----------|
| L1 | 页面顶级容器方向 | 检查根元素 display / flex-direction | 纵向排列 → column/flex-direction:column；横向 → row |
| L2 | 区块数量与顺序 | 从上到下列出设计图区块名，逐一在 template 找到对应节点 | 数量完全一致、顺序完全一致 |
| L3 | 单行 vs 多行卡片布局模式 | 含多行内容的卡片是否用了 flex-direction:column 或 column 布局 | **禁止多行内容全部挤在一行的错误**（如个人信息页的昵称/手机号/性别必须分行显示） |
| L4 | 固定区域定位 | 底部栏/导航栏定位方式 | 设计图固定 → position:fixed + 正确的 top/bottom/left/right |
| L5 | 滚动区域边界 | scroll-view height 计算是否排除固定区域 | 内容区不被遮挡、不产生无法滚动空白 |
| L6 | 行内元素闭合完整性 | 逐行检查 row 容器内子标签闭合情况 | 每个 row 的直接子元素数量与视觉一致 |

**通过条件：6/6 PASS。有 FAIL → 修复(≤2次/轮) → 重跑本轮。2次后仍有 FAIL → 带入下一轮。**

| # | 检查项 | 校验方法 | 允许偏差 |
|---|--------|----------|----------|
| V1 | 页面背景色 | 对比 background-color | 完全一致 |
| V2 | 卡片背景色/边框色/圆角值 | 容器样式对比 | 圆角 ±4rpx |
| V3 | 卡片内边距 padding | 测量文字到卡片边缘距离 | ±8rpx |
| V4 | 卡片间距 margin-bottom | 测量两卡片间隙 | ±8rpx |
| V5 | 标签字号/字重/颜色 | 样式对比 | 字号 ±2rpx，颜色完全一致 |
| V6 | 正文/次要文字字号颜色 | value/input 样式 | 字号 ±2rpx |
| V7 | 头像/图标尺寸 | width/height | ±8rpx |
| V8 | 按钮高度/背景色/文字色/圆角 | btn 样式块 | 高度 ±8rpx，颜色完全一致 |
| V9 | 分割线颜色与粗细 | divider 样式 | 颜色接近，粗细 1-2rpx |
| V10 | 特殊组件样式（开关/Tabs） | 选中非选态对比 | 视觉效果一致 |

**通过条件：10/10 PASS。有 FAIL → 修复(≤2次/轮) → 重跑本轮。2次后仍有 FAIL → 带入下一轮。**

| # | 检查项 | 校验方法 |
|---|--------|----------|
| I1 | 导航返回路径有兜底 | navigateBack 有 fail 回退逻辑 |
| I2 | 所有 @click handler 在 methods 中定义 | 全局搜索确认无遗漏 |
| I3 | v-model 绑定指向存在的 data 字段 | 变量在 data/computed 中声明 |

### 还原度判定

**每轮修复机制（流程图）**：

```
第 N 轮 第 1 次检查 → 有 FAIL → [修复 1/2] → 重跑当前轮全部项
第 N 轮 第 2 次检查 → 仍有 FAIL → [修复 2/2] → 重跑当前轮全部项
第 N 轮 第 3 次检查 → 仍有 FAIL → ⚠️ 本轮修复额度用尽，携带 FAIL 项进入下一轮
```

- **三轮全 PASS** → 可交付，还原度 ≥ 95%。
- **某轮 2 次修复后仍有 FAIL** → 停止本轮修复，剩余 FAIL 项带入下一轮（下一轮享有新的 2 次额度）。
- **三轮后仍有未解决 FAIL** → 从第一轮重新循环（每轮重置 2 次额度）；循环 3 次（共 9 轮）后同一 FAIL 仍无法通过 → 告知用户卡点原因及人工介入建议。
- **交付时必须附三张完整检查结果表**（含每项 PASS/FAIL、修正记录、修复次数统计）。

## 8. 交付前确认

交付前必须能明确说明：

- 页面文件创建或修改了哪些内容。
- 路由是否已创建或补齐。
- 多状态如何在单页内实现。
- 三轮定向精修分别改了哪些内容。
- 本次语法检查和三轮定向精修是否完成。
- **CSS 样式是否已按 `uni-css-guard` 技能完成跨端兼容审查**，哪些高风险写法已被替换或条件编译兜底。
