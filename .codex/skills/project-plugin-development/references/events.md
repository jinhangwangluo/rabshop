# 事件声明与处理

插件只能消费清单中声明的事件；先从项目事件目录选择既有事件，不能把尚未预埋的事件当作可用接口。事件名使用小写点分隔，插件自有发布事件必须以 `plugin.{code}.` 开头。

同一业务事实只生成一个 `event_id` 和一条 Outbox。多个插件订阅时由内核按清单、启用状态、运行端和商户授权筛选，并按 `priority + plugin_code + handler` 稳定排序；异步投递使用独立 `delivery_key`、重试和死信，插件之间互不阻塞。插件之间不能依赖异步优先级建立先后关系，应发布后续事件或声明经内核校验的显式依赖。

同步 `guard/filter` 必须串行、失败关闭，任一拒绝、异常或超时都阻止核心业务；处理器只能修改自己的 `plugin_payload` 命名空间。异步 `observer` 必须使用 `idempotency_key` 幂等，日志只保存脱敏错误和载荷哈希，不保存完整业务载荷。

初始化脚手架只声明示例事件，不替用户决定库存来源、资格、限购、锁库存期限或退款规则。业务规则冻结后再实现处理器、迁移和测试。
